## Costs and limits

- #1423's unique Guardian reviews consumed **89,239 ms** aggregate review-processing time and **3,279,786 model-reported total tokens** (3,274,976 input, of which 2,986,496 cached; 4,810 output), per #1423. The cached input is **part of** input, not additional tokens. These calls include direct Codex implementation after user-authorized takeover, and cannot be attributed wholesale to routine GLM worker operations.
- #1423 records a final parent counter of 23,206,542 model-reported tokens (including cache). The Guardian and parent counters describe different processes; no estimate of **avoidable** or billed token cost follows without per-action classification and controlled before/after telemetry.
- #1420 and #1399 do **not** provide a comparable complete Guardian per-invocation ledger in the referenced issue records. Neither a before/after reduction ratio nor Safety/Quality Delta is established.
- The ZIP raw transcripts referenced in these issues, the installed Codex rules directory, live CLI version, live `risk_level` ledger for all actions, and a matched before/after rollout were not accessible via this session's GitHub-only interface. Issue audit findings are a secondary, explicitly identified record of prior raw inspection, not a claim that this PR reread those ZIP bytes.

## Current repository-owned boundary

- [`codex/rules/glm-worker.rules`](../codex/rules/glm-worker.rules) currently supplies `allow` prefix rules for **bare** `glm-worker`, `glm-parent-action`, and `glm-codex-context` argv. The parent-action prefix matches even unknown subcommands; the **CLI's own closed grammar/staging and lifecycle guards**, not the execpolicy prefix, are relied on for semantic rejection. Do not treat a prefix allow as arbitrary shell/Git/Push authorization.
- [`glm-worker/internal/workflow/quality_gate_rules_test.go`](../glm-worker/internal/workflow/quality_gate_rules_test.go) already checks bare positive facades and negative direct Git operations. This PR extends that matrix with canonical install/publication entries and shell-compound/direct-install negative cases; it does **not** change allow rules or installation behavior.
- [`tests/install_smoke.sh`](../tests/install_smoke.sh) copies the managed rule byte-for-byte to the installed Codex rules destination in its isolated fixture. This is a source-to-fixture test, **not** proof of the user's currently installed Codex CLI/policy version.
- [`codex/instructions/execution-permission.md`](../codex/instructions/execution-permission.md) separates task authority, execution permission, and execution result and defines escalation for genuinely missing scope. For `glm-parent-action controller-publication`, the remote Push is an important irreversible effect; automatic authorization must not be invented by this evaluation.

## Validation and Codex handoff

**Performed here:** GitHub main policy/test/installation fixture inspection, current Task and rules review, comparison against the three specified historical Audit issue records, and PR source diff inspection. **Not performed here:** local Docker Go tests, actual Codex `execpolicy check`, live installation comparisons, new Guardian invocations, or matched before/after rollout. The Go checks deliberately skip when no Codex CLI is present; any CI pass without that CLI is **not** authorization-matrix evidence.

**Codex decisions and follow-up:** (1) capture installed managed rule bytes, Codex CLI version and raw argv/sandbox profile for a bare facade plus compound shell, local verification, install and real publication; compare with the source expectations; (2) determine whether the repeated `origin/main` refusals are truly external reviewer policy behavior versus a repository-owned command-composition or permission-profile defect; (3) if and only if a safe repo-side defect is reproduced, patch it while keeping required remote-Push approval and publish a controlled before/after rollout with Guardian counts, unnecessary-denial rates, human waiting, model/tool reentry, token and Quality Delta; (4) if the problem is external and cannot be remediated here, retain **unproven** effectiveness and quantify remaining human dependence. The proposed test matrix alone does not demonstrate unattended success, and this Task must not be declared complete on its strength.
