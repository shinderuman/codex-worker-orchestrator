# Go規則
- private識別子はcamelCase、public識別子はPascalCase。
- エラーには必要なコンテキストを含め、サイレント失敗より明示的なエラーハンドリングを優先する。
- Go commandは標準的な`cmd/<name>/main.go` + `internal/`構成を基本とする。
- `cmd/<name>/main.go`は起動・最終error処理だけの薄いentrypointにし、flag parsing、repository探索、validation、永続化、business logicを置かない。
- 実装責務は既存packageを優先し、同じ責務のhelper・wrapper・interfaceを並行増殖させない。
- 現行のmanaged worker sandboxでは、orchestratorのisolation設定によりBashが既定のGo build cache位置への書込みとUnix socket bind(`bind: operation not permitted`)を機械的に拒否する。Docker test backend契約が有効なときだけ、解決済みの選択されたDocker endpointのUnix socket接続と`DOCKER_HOST`固定が例外として許可される。endpoint未解決・tcp/remoteでは許可なしで失敗する。これらは実行環境側の既知capability制約であり、検証対象実装の不具合ではない。この記述は現行sandboxの保証であり、将来や別実行環境での成否を断定しない。
- build・vet確認は、対象repositoryが`$TMPDIR`配下のdeterministic GOCACHEへ固定した入口を提供する場合は必ずその入口を使い(codex-configではrepository rootの`./goquality vet`・`./goquality build`)、提供がない場合だけ`GOCACHE`を`$TMPDIR`配下へ指定して対象moduleのdirectoryで`go build ./...`・`go vet ./...`を実行する。既定cache位置のままでの再試行はしない。
- 診断用の`go test`(focused package・`-run`・`-race`等、正規Quality Gate外の局所検証)は、対象repositoryがGo version契約とtest引数渡しを持つ固定入口を提供する場合は必ずその入口を使う(codex-configではrepository rootの`./goquality test <go test args...>`)。Darwin ARM64でDocker test backend契約を持つcodex-configでは、この入口はMac native実行の選択肢を持たずLinux ARM64 Docker診断へ機械的にroutingされる。同じ条件のworker sessionでは`go test`直接実行をBash deny rule(相対・絶対path・`-C`形式・versioned go実行形式を含む)とPATH上の`go` proxyの両方が拒否する。契約のないrepository・hostではこのdenyとproxyは適用されず、入口は従来のnative診断のままである。Docker利用不能時も入口は失敗となり、Mac nativeへの迂回や検証省略をしない。入口が規定Go versionへ解決できない場合も検証として実行せず失敗として報告する。機械証跡行(codex-configでは`goquality-linux-diagnostic`行とcontainer内`goquality-diagnostic`行)を検証logと一緒にREPORT artifactへ残し、自然言語のTESTS宣言だけで代用しない。診断実行のPASSを正規Quality Gateのvalidation証拠や`parent_validation`へ昇格させない。
- Unix socket bindを必要とするtestはDocker診断入口のcontainer内では成立するため`./goquality test`で実行する。containerのLinux platformでは実行されないdarwin build tag専用の検証義務(codex-configでは正規gateのDarwin補完対象)と、現在のsessionのsandboxではDocker socketが許可されない遷移状態の検証義務は、worker環境で成立しないため`IMPLEMENTED`報告の`parent_validation` typed pair(working dirは対象module directory)へ一度だけ委譲する。`NEEDS_SOL_DECISION`では両fieldをJSONから省略し、必要な親validationを`test_obligations`へ記載する。validation義務は保持し、Sol判断後の`IMPLEMENTED`報告で同じtyped pairを返す。事前に既知の場合は成立確認のための失敗実行を挟まない。委譲すべき義務へskip一覧・一部packageだけの再実行、それらの成功による全体義務の代替をしない。typed pairで表現できない検証義務は未検証として報告する。
- 既知capability制約の拒否signatureは既定cache位置への書込み拒否、socket bind拒否、Docker test backend契約下でのDocker Unix socket接続拒否だけとする。それ以外の失敗は未知の実装failureとして失敗として報告し、環境問題へ分類せず無条件retryで隠さない。
